# Hardening reference

Detail behind [README.md](README.md): every hook, the decision protocol, subagent scopes, the MCP policy, the security model and how to test and debug.

## Registration

All hooks are registered by [settings.hooks.json](settings.hooks.json) as one plain shell string per hook:

```json
{ "type": "command", "command": "node hardening/hooks/pre-tool-use.mjs", "timeout": 20 }
```

Both hosts run it from the repository root. Claude Code runs shell-form commands in Git Bash (PowerShell when Git Bash is
missing) with the project root as the working directory and `CLAUDE_PROJECT_DIR` exported. GitHub Copilot CLI also reads
`.claude/settings.json` and `.claude/settings.local.json` (in a folder trusted in the CLI) and runs the string in
PowerShell on Windows and bash elsewhere, from the repository root, with `CLAUDE_PROJECT_DIR` exported too (Copilot CLI
1.0.94 and Claude Code 2.1.293, probed 2026-10-08). The string therefore carries no `args` (the CLI ignores them and
runs bare `node`, which fails on the payload and then refuses every tool), no `${CLAUDE_PROJECT_DIR}` (the CLI does not
substitute it and PowerShell expands it to nothing) and no quotes or inline code (the CLI's PowerShell call drops them).
Claude Code's docs recommend `${CLAUDE_PROJECT_DIR}` for a hook that must run from any working directory; the relative
form is used because the measured working directory is the project root in both hosts and the CLI accepts nothing
else. The payload always arrives as JSON on stdin; environment variables such as `$TOOL_INPUT` are empty and must never
be used. A hook that cannot start does not block (Claude Code docs, Hooks), which is why the installer refuses the pack
without Node 18.17+ on PATH. Neither does one that times out, so git cannot hold a hook that long: one git call times out
after 3 s (`BI_HARNESS_GIT_TIMEOUT_MS` raises it to at most 10 s) and all git calls of one hook process share 12 s; the
Stop gate's share 60 s under Claude Code (90 s in this file) and 20 s under Copilot CLI and VS Code (`BI_HARNESS_HOST`;
30 s in `copilot-cli.hooks.json` and `vscode.hooks.json`), each at least a third below its host's timeout (`gitBudgetMs`
in `hooks/lib/common.mjs`; `tests/self-protection.test.mjs` checks all three files; [README](README.md#limits), Slow
machines).
`tests/copilot-claude-dialect.test.mjs` runs the registered string through bash, `pwsh` and
`powershell` from a project copy, with and without `CLAUDE_PROJECT_DIR`.

## Subagent scopes

`agent-scope.mjs` reads `agent_type` from the payload and looks it up in `agentScopes` in `harness.config.json` (defaults in `hooks/lib/common.mjs`). The main agent has no scope. The hook's command takes no arguments: the flags `--read-only`, `--mcp-read-only` and `--write` of earlier versions replaced the configured scopes, so they are gone, and an argument makes the hook refuse every call.
Because it is a settings-level hook, the agent files carry no `hooks:` frontmatter and stay plain Markdown. Denials are written to `security-events.jsonl`.

The scopes of every subagent are in `agentScopes` in `hooks/lib/common.mjs`; `tests/agent-scope.test.mjs` checks that every file under `.claude/agents/` has one, except the main-session agent named by `agent` in `.claude/settings.json`, which must have none.

- `readOnly` (the reviewers, the validator, bi-source-analyst, bi-rdl-analyst): Edit and Write, and any shell command that could change files or git state, are denied. Each statement, pipe stage and nested `$( )`/`{ }` is judged by the program it really runs (folder and `.exe` dropped, git options before the subcommand skipped, `VAR=x`, `env` and `xargs` looked through): redirects, `sed -i` in any position, `rm`, `cp`, `tar`, `patch`, `dd`, `find -delete`, every git subcommand that is not a read (`commit`, `config`, `worktree`), `npm install`, interpreters, shells and script files (`node -e`, `py -c`, `powershell -c`, `cmd /c`) and the PowerShell cmdlets and aliases that write (`ni`, `copy`, `Set-Content`, `Expand-Archive`) are denied. The validator (also as the npm checks `npm --prefix hardening test` and `run validate`, which take words only after `--`), the RDL comparison (`node hardening/scripts/rdl-compare.mjs`), the hook-pack check (`node hardening/scripts/check-hooks.mjs`, no argument) and harmless version probes (`node --version`) are allowed, each as the whole command: no redirect, no second command, no extra line.
- `write` globs (bi-tmdl-modeler `**/*.SemanticModel/**`, `**/*.tmdl`, `docs/sources/**` and `reports/*/sql/**`; bi-pbir-editor `**/*.Report/definition/**` and `**/*.Report/StaticResources/**` (theme files);
  bi-rdl-editor `**/*.rdl`, `**/*.rds`, `**/*.rsd`, `**/*.rptproj`; bi-ssis-editor `etl/*/**` (a project folder under `etl/`: packages, project files, `sql/` and `jobs/` scripts); bi-doc-generator `docs/**` and `reports/*/docs/**`; the modeler and the RDL editor also get the test folders `docs/tests/**` and `reports/*/tests/**` (the SSIS editor `docs/tests/**` only), the modeler, the PBIR editor, the RDL editor and the SSIS editor `TASKS.md` (bi-doc-generator does not); `tests/agent-scope.test.mjs`): a write outside the scope is denied, and so is any shell command that could change files or git state (the same judgement as `readOnly`): the editors change files only through Edit/Write.
- `mcpReadOnly`: the model editors may read MCP metadata; connection changes, writes and unknown operations go back to the main agent.

## Decision protocol

| Event | Block | Add context |
|---|---|---|
| PreToolUse | `hookSpecificOutput.permissionDecision`: `deny`, `ask` or `allow` (+ reason); exit 2 on a crash; under GitHub Copilot CLI, recognised by `COPILOT_CLI`, which runs the guard once per registration, a later copy of the same ask for the same call stays silent and is logged as `repeat` (`hooks/lib/ask-once.mjs`: the session, the payload's instant, the tool, its raw arguments and the reason; whatever it cannot read or record asks); the GitHub Copilot app and VS Code's Copilot harness are not probed for it and still prompt per copy unless they set `COPILOT_CLI` | `hookSpecificOutput.additionalContext` |
| PostToolUse | `decision: "block"` + `reason` (the tool has already run) | `additionalContext`, `updatedToolOutput` |
| UserPromptSubmit | exit 2 + stderr (Claude Code drops the message; Copilot CLI treats exit 2 as a warning and the run continues; VS Code hands stderr to the model as a blocking error and does not document withholding the message) | `additionalContext` (dropped by Copilot CLI) |
| Stop, SubagentStop | `decision: "block"` + `reason` | `systemMessage` warns the user |
| SessionStart | none | `additionalContext` |

## MCP policy (Path A with the pack)

- Specific read operations on recognised model tools pass automatically; there is no broad `Get*` match. Writes and unknown operations go to the main agent and the approval flow; the server's own read-only mode stays in force. On a named local connection, ordinary writes (measures, columns, tables, DAX functions, calculation groups, calendars, hierarchies, perspectives, cultures, translations, model properties, transactions; create and update) are a plain ask that `auto` approves and logs; Tier 2 writes (deletes, renames and moves, relationships, partitions, and a partition source, M expression, data source, connection string, provider or named expression named in any table or model write, Power Query expressions, parameters and query groups, refresh, refresh policy, storage mode, database writes) and any other operation always ask (`lab` runs them). Remote or unnamed connections are the floor.
- For DAX execution the pack looks for one known result shape and an integer `maxRows` from 1 to 50; an unrecognised shape asks for review. The query is read from the request's `query` field and nothing else: a call without one, or with a second text that contains `EVALUATE` (a description, a note), asks. Comments (`//`, `--`, `/* */`) are ignored only outside string literals, quoted table names and bracketed names; a string, name or block comment that never closes asks. `TOPN`, `SAMPLE` and `TOPNSKIP` are as row-level as their table (`TOPN(5, Customer)` asks; over `SUMMARIZECOLUMNS` it passes). A query built on `INFO.*`/`INFO.VIEW.*` functions that names no table column returns metadata and passes (`INFO.DATASOURCES` asks). Personal columns: English, Turkish and common European words built in (the SQL read switch's vocabulary, one list for both guards), plus `sources.sqlRead.personalColumns`, which also counts as a whole word of a longer column name when the column is named with its table (`Customer[Home Fax]`). In a table named like a customer, employee, salesperson, contact, person, client, member, patient, student, user or rep, the columns that hold a person's name (`Name`, `Full Name`, `First Name`, `Last Name`, `Display Name`, `<table word> Name` and longer names ending in one of them: `Customer[Name]`, `Employee[Display Name]`, `Customer[Customer First Name]`) ask like the table's key does, anywhere in the query; a manager's or supervisor's name (`Employee[Manager Name]`, `Store[Manager Name]`) asks in any table; `Customer[Country Name]`, `Customer[Company Name]`, `Customer[Account Name]`, `Employee[Department Name]` and `Product[Name]` pass. This is not a DAX parser and not proof that no personal data is present.
- Every alias in `mcp.powerbiServers` (default `powerbi-modeling` and `powerbi-authoring-local`, Microsoft's sample name) and `mcp.powerbiServer` gets the same policy and masking, and so does any server whose tool is one of the modeling server's 21 `*_operations` tools, unless `sources.sqlRead.mcpServers` names it. One agent owns the connection and the writes for a model ([docs/harness/MCP.md](../docs/harness/MCP.md)).
- Where MCP is prohibited (Path B) none of this applies: there is no MCP call to police.

## Security model

| Risk | Control | Limit |
|---|---|---|
| Reading secrets or the data cache | permission rules; PreToolUse file and shell checks | shell analysis is textual |
| Writing a secret into a file | Edit/Write content check, validator, pre-commit, CI | known patterns only |
| Data coming back from MCP | bounded query shape plus `maxRows`; output PII masking | an aggregate can still contain personal data; an answer over Claude Code's MCP output limit is saved to a file the hook never masks: only reads that name the file get the masking (not a wildcard, a copy or a renamed file), and a slice whose keys were stripped (`jq -r '.rows[].Phone'`) gets the text rules only |
| Writing to the wrong model | writes, connection changes and unknown operations ask; deploy denied; a query or write on a connection the session never confirmed asks | the hook knows connection names, not whether the model matches the request |
| A query that writes to a database or returns personal rows | SQL read switch: writes denied (also in a text too long to read in full); off by default (every query asks); on: only bounded read-only queries against listed servers without personal columns pass | textual analysis; a query's cost is not bounded |
| A subagent leaving its scope | scoped Edit/Write, read-only MCP, shell write checks | not an OS sandbox |
| The pack's hooks switched off in the settings (a matcher that matches nothing, another event, a timeout that always expires, another type, a word or an argument in the command) | the PreToolUse guard compares each hook entry of the pack with what the settings file holds now, and in the Copilot hook files `.github/hooks/*.json`, and denies a change or removal; adding hooks passes; a change of `env.NODE_OPTIONS`, `env.PATH` or `env.PATHEXT` in the settings and the deletion of a hook file of the pack are denied | managed settings and hook registrations outside `.claude/settings*.json` and `.github/hooks/` |
| A broken commit | validates the staged snapshot of the Git index | not a DAX/TMDL compiler or full JSON Schema validation |
| Per-user files committed (`.pbi/localSettings.json`, `*.tmuo`) | refused when staged, reported when tracked | known file names only |
| A project path spelled differently (symlink, junction, macOS `/tmp`, Windows 8.3 short name, trailing dot, alternate data stream) | the PreToolUse guards check every spelling (as written and resolved); stream and device paths are denied; shell write targets are judged without trailing dots and `:stream`; shell commands are judged with short names spelled out; the file words of every shell program but a printer, and every redirect target, are also judged as the shell opens them, through a link or a `..` after one, a glob by its folder, a PowerShell list by item and a Windows device, local share or stream spelling by its drive path (audit 2026-10-31, A1 and R3 to R5) | a path that is really outside keeps the normal permission flow; a variable, `~`, a wildcard in the first segment and a path a command computes are judged as written |
| A share path (`\\host\share`, `//host/share`) while the project is not on a share | judged as outside without resolving it: the guard opens no connection to a host a command names | a project that is itself on a share still resolves its own paths |
| Force push, bypassing protection | permission, shell and Git hook checks | local hooks can be skipped; require branch protection on the server |

`PostToolUse.updatedToolOutput` changes what the model sees after the tool has run: masking does not undo a network call, a written file or the original telemetry, and a failing hook gives no
guarantee. The first defence is not to request data you do not need. Claude Code's `sandbox.enabled` adds OS-level isolation these hooks do not; enforce organizational policy with Claude Code's
[managed settings](https://code.claude.com/docs/en/settings) (an administrator's file the user cannot override), platform permissions and a required CI check, not repository settings a user can edit.
If a credential is found: report file, line and type without the value, then revoke or rotate it; deleting it does not clean Git history, and rewriting history is a human decision.

## Test and debug

```bash
npm --prefix hardening test                # every hook, with real stdin JSON
node hardening/scripts/check-hooks.mjs     # which hook file is broken (file:line)
P=$(pwd -W 2>/dev/null || pwd)             # Git Bash on Windows: C:/... (Node reads /c/... as C:\c\...)
echo '{"tool_name":"Write","tool_input":{"file_path":"'"$P"'/notes.md","content":"x"}}' \
  | CLAUDE_PROJECT_DIR="$P" node hardening/hooks/pre-tool-use.mjs
claude --debug                             # hook details: ~/.claude/debug/<session>.txt
claude -p "I am testing this repo's hooks. Run: cat .env" --model haiku --max-turns 3 --strict-mcp-config
tail -n 3 .claude/logs/security-events.jsonl   # expect "decision":"deny","tool":"Bash"
```

`instructions.jsonl` lists the rules and `CLAUDE.md` files that loaded; an `AGENTS.md` read through Claude Code's default setting does not fire `InstructionsLoaded`, so it does not appear there (`/context` shows it).
In `-p` mode hooks run, but `permissions.allow` rules from the project are ignored until workspace trust is granted (accept the trust dialog once in an interactive session). `/hooks` lists the loaded hooks.
Diagnose a problem by running the relevant hook's test; do not disable the failing check.

## Adding a hook

1. Logic in `hooks/lib/` (`policy.mjs` decisions, `validators.mjs` checks); keep the entry script thin.
2. A guard uses `runHook(..., { failClosed: true })`; a logging or context hook is fail-open.
3. A test in `tests/` that triggers it; build a fake secret at run time by joining parts (`tests/copilot-claude-dialect.test.mjs`
   shows the pattern), never as a literal.
4. Register it in `settings.hooks.json` as `node hardening/hooks/<name>.mjs` (no `args`, variables, quotes or inline
   code: Registration above); verify with `npm --prefix hardening test` and `claude --debug`.
