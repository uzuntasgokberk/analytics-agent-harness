# PBIP anatomy

Sources: Microsoft Learn PBIP pages and the TMDL overview, reviewed 2026-09-29. Learn still labels
PBIP, PBIR and TMDL storage as preview; check Learn before asserting current status or limits.

## Folder map

```
<repo>/<folder docs/conventions.md names; recommended powerbi/>
├── <Name>.pbip                    shortcut to the report folder; optional (open definition.pbir instead)
├── <Name>.SemanticModel/
│   ├── definition.pbism           [required] model descriptor; version 4.0+ allows TMDL (the harness needs TMDL)
│   ├── definition/                [TMDL] the model as text
│   │   ├── database.tmdl, model.tmdl      compatibility level, culture, `ref table` order
│   │   ├── tables/<Table>.tmdl            one file per table: columns, measures, hierarchies, partitions
│   │   ├── relationships.tmdl             all relationships
│   │   ├── expressions.tmdl               shared M expressions and parameters
│   │   ├── roles/ perspectives/ cultures/ one file per role, perspective, culture
│   │   └── dataSources.tmdl, functions.tmdl   when present
│   ├── model.bim                  [TMSL] single JSON file instead of definition/: not supported by the harness
│   ├── DAXQueries/ TMDLScripts/   saved DAX query view and TMDL view tabs
│   ├── diagramLayout.json         Desktop-owned
│   └── .pbi/                      localSettings.json [local], cache.abf [DATA, local],
│                                  editorSettings.json (shared), unappliedChanges.json (pending Power Query)
├── <Name>.Report/
│   ├── definition.pbir            [required] binds the model: byPath (local) or byConnection (Service)
│   ├── definition/                [PBIR] version.json, report.json, reportExtensions.json, pages/, bookmarks/
│   ├── report.json                [PBIR-Legacy] Desktop-owned
│   ├── StaticResources/RegisteredResources/   themes, images (loaded resources may be edited)
│   ├── CustomVisuals/             private custom visuals only
│   ├── mobileState.json, semanticModelDiagramLayout.json   Desktop-owned
│   └── .pbi/localSettings.json    [local]
├── .platform                      per item: Fabric Git integration metadata; config.logicalId is never changed
└── .gitignore                     Desktop default: **/.pbi/localSettings.json and **/.pbi/cache.abf
```

Desktop creates a missing required file on the next save. It writes `.gitignore` only when none exists.
TMDL syntax and object rules: `bi-semantic-model` → `references/tmdl-guidelines.md`; Microsoft's own PBIP folder
reference: `references/pbip.md` in the same skill. PBIR structure: skill `bi-pbir-report`.

## Formats and versions

| File | Version | Meaning |
|---|---|---|
| `definition.pbir` | 1.0 | report stored as PBIR-Legacy (`report.json`) only |
| `definition.pbir` | 4.0 or higher | PBIR-Legacy or PBIR (`definition/`) |
| `definition.pbism` | 1.0 | model stored as TMSL (`model.bim`) only: not supported by the harness |
| `definition.pbism` | 4.0 or higher | TMSL or TMDL (`definition/`); the harness works on TMDL |

`byPath`: relative path with forward slashes to the model folder; absolute paths are not supported and
Desktop opens the model in edit mode. `byConnection`: a Service model; Desktop does not open it in edit
mode. Several `.pbir` files may coexist (for example `definition-liveConnect.pbir`); Fabric Git
integration reads only `definition.pbir`.

## Who owns what

| Files | Rule |
|---|---|
| `tables/*.tmdl`, `relationships.tmdl`, `expressions.tmdl`, `roles/*` | text edits allowed; Tier 2 areas are listed in AGENTS.md |
| `definition/**` of a report (PBIR) | text edits allowed; names, schema and references must stay valid |
| `report.json` (Legacy), `mobileState.json`, both diagram layouts | Desktop-owned; external edits unsupported |
| `.pbi/localSettings.json`, `.pbi/cache.abf` | local only; never commit; `cache.abf` holds data, never read |
| `LocalDateTable_*`, `DateTableTemplate_*` | generated by auto date/time; do not edit |
| `.pbi/unappliedChanges.json` | pending Power Query work; applying it overwrites external M edits |
| `.platform`, `definition.pbir` binding, `.gitignore` | user decision (`logicalId` never changes; a copied item gets a new one) |

With a `cache.abf` present, Desktop loads the data and overwrites the model definition with the project
metadata; without it, Desktop opens the definition without data.

## External edits

- Desktop can detect changes made outside it and offer to apply them, but Microsoft's semantic model page
  says Desktop is not aware of changes by other tools. Apply the prompt or restart Desktop, and always
  restart after renaming PBIR files or folders.
- A bad edit is either blocking (invalid schema or missing required property: Desktop will not open the
  project and names the file when it can) or non-blocking (auto-fixed with a warning, such as an invalid
  `activePageName`).
- PBIR page, visual and bookmark names may contain letters, digits, `_` and `-`; other names are ignored
  as private files.
- Encoding is UTF-8 without BOM. Desktop writes CRLF; set Git line endings (`.gitattributes`, autocrlf).
- Filters, slicers, bookmarks and formatting can persist real data values in PBIR files.

## Limits

- Windows path limit of 260 characters: keep the repo root short.
- No saving a PBIP straight to OneDrive or SharePoint; a synced local folder can still fail.
- Not supported: sensitivity labels, Report Linguistic Schema (Q&A synonyms), Desktop for Report Server,
  deploying a project to Azure or SQL Server Analysis Services.
- Service limits per PBIR report: 1,000 pages, 1,000 visuals per page, 1,000 resource files, 300 MB of
  resource files, 300 MB of report files.
- Fabric REST APIs do not get or set RLS members or incremental refresh partitions.

## Delivery and migration

| Topic | Fact |
|---|---|
| Publishing routes | Fabric Git integration; Fabric REST APIs; Desktop Publish |
| Desktop Publish | uses a temporary PBIX and deploys metadata **and** the local data cache |
| API deployment of a report | the report must use `byConnection` references |
| Fabric Git integration | the workspace syncs a directory of this repository; `byPath` when report and model share the workspace, `byConnection` otherwise; a service commit deletes non-definition files inside item folders; guide: [fabric-git.md](../../../../docs/harness/fabric-git.md) |
| PBIX and PBIP | convert only through Desktop Save As, not programmatically |
| TMSL to TMDL | one way in the UI; copy the project first. Required before the harness edits the model |
| PBIR-Legacy to PBIR | one way in the UI; Desktop keeps a backup for 30 days under `TempSaves\Backups` |
| New Service reports | created as PBIR; Learn says PBIR becomes mandatory at general availability |

The agent never deploys. For a release, give the user the route that fits (Git integration, pipeline,
Desktop Publish) and what to verify afterwards.
